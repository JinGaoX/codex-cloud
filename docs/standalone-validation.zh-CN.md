# iPhone 独立版验证记录

日期：2026-10-22；版本 `2.20.2-personal.2`；分支 `feat/iphone-standalone`。

本轮将应用业务从自建服务端迁移到手机浏览器，静态 HTTPS 仅分发安装和更新文件。
它不是 IPA，不在 iPhone 中运行 Node.js。实际内容来自用户配置且允许浏览器访问的 HTTPS 源。

## 已完成与已验证

- `npm test`：44 个文件、**600 项全部通过**；包括此前 551 项以及新增的 21 项直连 API、
  19 项独立 SW/缓存生成与 9 项独立媒体入口测试。
- `npm run typecheck`：通过。
- `npm run build:iphone`：纯静态导出成功，全部 Next.js API 路由从构建输入排除；
  约 55 个公开界面资源预缓存，首页 First Load JS 约 247 kB（非真机测速）。
- 系统 Chromium，430×932 手机尺寸，本机纯静态 HTTP 文件服务器，没有 Node 业务后台：
  首页无登录弹窗、无横向溢出；完整 SW 安装与激活；设置添加两个 HTTPS 测试源；
  一个源被模拟网络拒绝时另一个源成功搜索、详情与剧集列表展示、收藏成功；
  真实解码本机生成的 H.264/AAC MP4、保存第 7 秒进度并刷新恢复。
- 关闭页面、断网，再新建页面冷启动，首页、收藏和源配置仍可使用。
  整个流程记录到的同源 `/api/*` 请求为 **0**，未处理页面异常为 **0**。
- Apple 试播链接来自官方示例页面；真实 master/子清单返回 200，带 Origin 的响应允许 CORS，
  读取两字节的媒体 Range 返回 206。仅核验网络和来源，未据此宣称 iPhone 已播放成功。

浏览器中使用的 `example.invalid` 源和影片均是明确标记的受控夹具，未内置到产品源列表。
合成媒体实际解码也不代表真实影视源一定可播放。QA 脚本、结果和截图位于本会话独立证据包。

## 仍需 iPhone 15 Pro Max 实机确认

1. Safari 打开正式 HTTPS 地址，通过站点访问验证后“添加到主屏幕”。
2. 从主屏幕首次启动，联网等待本机资源保存完成；重开无普通浏览器地址栏。
3. 点 Apple 官方试播，检查原生 HLS、声音、暂停、快进/拖动、倍速、横屏及系统全屏。
4. 添加自己有权访问的 HTTPS JSON API，确认搜索、详情、选集、换源与收藏；
   被 CORS 拒绝的源应显示说明，页面和其他源继续工作。
5. 暂停后关闭/重开，锁屏与后台恢复后核对进度；断网重开查看本地收藏、历史及设置。
6. 在 Windows 保持关机的情况下完成上述操作。手机在线播放仍需联网；本应用不下载影视内容。

iOS 可能挂起或清理缓存/IndexedDB，Safari 与主屏幕 App 可能使用不同存储；
必须从主屏幕配置并定期导出。HTTPS/CORS、编解码器、源签名/防盗链与地区限制无法由纯 PWA 消除。

首次安装地址与实际发布结果以本会话最终交付为准；新 Sites 项目默认仅本人可访问，
初次访问可能需要登录当前 ChatGPT 账号。平台只托管程序文件，不接收本机收藏或源配置。
