# 搜索有结果但详情失败

日期：2026-10-25；版本：`2.20.2-personal.7`。

已发布：https://jingaox.github.io/codex-cloud/ 。程序源码提交
`1a897e41508c269c54c8dbdd34c0899e22e59e87`，静态发布提交
`4ccc06c5861f625ebdd63f7c8757afc485a51eb4`。
现有主屏幕 App 出现“应用更新已就绪”时，点“更新并重新打开”；不需要清除数据或更换安装地址。

用户截图中，搜索可显示“暴风”结果，但该来源详情请求显示通用网络错误，其他部分来源也失败或暂时停用。
这与此前 `chatgpt.site` 的整站 Cloudflare 错误页不同，当前页面和错误隔离仍在工作。

## 能确认的范围

通用提示由浏览器 fetch 被拒绝或响应体读取发生 TypeError 产生；浏览器不会向网页完整暴露 CORS、
TLS、网络中断等底层原因。因此不能仅凭截图判断是哪一种。
可见的 HTTP 错误、非 JSON、缺少播放地址有单独的错误提示。
源码审计未发现搜索结果的 sourceKey/vodId 串源或 URL token 丢失；详情仍请求用户配置的同一 HTTPS API。
取得用户实际地址后，服务器请求确认搜索响应 `Access-Control-Allow-Origin: *`，详情响应虽 HTTP 200，
却缺少该头。真实地址不写入公开配置或测试；这里只记录诊断结果，不上传用户配置。
从当前 App origin 的 Chromium 实际请求也确认：搜索能读取 3 条结果，原详情请求被浏览器以 TypeError 拒绝。

## 已修正的请求浪费与恢复操作

搜索用 `ac=videolist`，有些接口已经返回 `vod_play_url`。旧版只保留搜索展示字段，
点开详情时再请求一次；详情读取成功后，进入播放器还会请求一次。
新版只复用已实际返回且能解析出 HTTPS 播放信息的完整内容，以及成功的详情读取结果。
缓存保存在内存，按来源 URL、来源标识和影片 ID 隔离，并有短时有效期、条数和内存上限。
修改来源、内容过期、没有完整播放信息时仍访问详情 API，失败不放入缓存。
若详情发生通用浏览器网络错误且已有影片名，会向同一源重新搜索，只有精确相同影片 ID
并实际返回完整 HTTPS 剧集时才恢复。这使历史续播和冷启动不依赖上一页面的内存缓存。
未匹配 ID、明确 HTTP 错误或用户取消时不伪造成功，不递归请求详情。
这不是影片下载，不会把私人源配置写入代码仓库或把请求发给未知代理。

详情失败后可以点“重试”，不必关掉弹窗重开；关闭或取消的旧请求不会覆盖新结果。

## 无法由纯 PWA 保证的事情

电脑服务器版可以代客户端请求接口；当前手机独立 PWA 由浏览器直接访问 API 和视频。
如果接口持续不允许浏览器跨域读取，或视频需要源站专属鉴权/请求头，单靠页面代码不能保证兼容。
此时需要可用的兼容源，或另外评估有授权的轻量服务器请求服务；
不能把 mode:no-cors、不明公共代理或模拟测试当作真实可播放的解决办法。

用户提供的这一接口已观察到搜索/详情跨域头不一致；原始 HTTP 对比不能代替所有设备网络验证。
不下载真实影片，实际视频解码、声音、全屏和后台恢复仍需 iPhone 复测。

## 本轮验证结果

- 48 个测试文件、685 项单元测试通过，TypeScript 与两个静态构建通过。
- 受控浏览器回归：搜索已有剧集时，详情到播放器不发送额外详情请求；冷重开经相同 ID 搜索恢复并续播约 7 秒；
  不完整搜索在详情失败后保留其他结果，可点至少 44px 的重试按钮；成功后播放器不重复读详情。
- 冷恢复故意把同名错误 ID 放在正确记录前，仍只恢复原 ID，没有请求错误记录的媒体。
- 实际用户 API 的浏览器元数据验证：首次搜索无需详情请求即可显示目标的 10 集；
  完整重开后，原详情确实被浏览器拒绝，再由同 ID 标题搜索恢复 10 集。全部真实媒体和海报请求主动阻断，
  不把“剧集显示正常”冒充真实影片已播放成功。
- 实际 GitHub Pages 同一浏览器上下文从 personal.6 更新到 personal.7，先等待明确的更新操作，
  更新后 PIN、源配置、选中项和收藏逐项保留；没有未捕获页面异常。

上述浏览器使用 Chromium 模拟触控，iPhone 真机搜索与视频播放仍待用户复测。
