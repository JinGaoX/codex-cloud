# iPhone 15 Pro Max 独立版 PWA

此构建把公开应用界面、搜索与详情请求逻辑放在设备端，不运行 Next.js API、搜索聚合服务器或视频代理。
首次安装/更新使用 HTTPS 静态网址分发应用文件；本机缓存完成后，电脑和静态网址暂时不可访问时，
仍能打开已缓存的界面、设置、收藏及观看历史。搜索和视频内容来自你配置的合法数据源，需要联网，
并受 Safari 的 HTTPS、CORS 和媒体兼容性限制。本机缓存界面不等于下载影片。

## 安装及确认本机保存

1. 在 iPhone **Safari** 打开正式 HTTPS 地址的 `/install.html`。如从 ChatGPT 内打开，先通过菜单选择
   用 Safari 打开。私人网址首次访问或平台会话失效时，需要使用有权访问此 Site 的 ChatGPT 账号完成平台验证。
2. 点安装页“打开 LibreTV”，再点 Safari **分享 → 添加到主屏幕**；如有“作为网页 App 打开”，保持开启。
   推荐先添加图标，再设置本机密码，避免把 Safari 标签页的数据误认为主屏幕 App 的数据。
3. **从主屏幕图标首次启动时保持联网**，自行设置并确认 **6 位数字本机 PIN**。无需另注册应用账号，
   没有内置默认 PIN。Safari 与主屏幕 App 的密码、缓存和数据库可能独立，平台也可能再次要求访问验证。
4. 首页底部会显示“正在将应用保存到本机”；完整界面资源下载成功、Service Worker 激活后，提示消失。
   如提示尚未保存成功，先检查网络和系统存储空间后重新打开，不要把失败安装当作已经可离线。
5. 在这个主屏幕 App 的设置内添加实际合法 HTTPS API，再搜索、选集和播放。手机直接访问 API/媒体，
   不提供后台搜索或视频代理。CORS/证书/网络错误会说明可能原因；拒绝跨域的源不能靠纯 PWA 自行解除限制。
6. 导出备份后，断网关闭再打开主屏幕图标，确认能用本机 PIN 解锁并查看界面、设置及已有收藏/历史；
   联网后恢复搜索和播放。完整缓存、PIN 离线解锁与实际播放仍需真实 iPhone 验证，桌面测试不能替代。

## 本机 PIN 的使用范围

- PIN 仅在此设备/入口验证，用于锁定应用界面；它不加密本机数据，不是影片 API 的密码，
  也不替代私人托管网址的 ChatGPT 访问验证。平台在线访问或更新验证失效时，仍需按平台要求登录。
- 每次刷新或重新加载 App 都需解锁；普通切到后台不自动锁定，以便恢复播放。系统回收后重载会再次要求 PIN。
  可在 **设置 → 数据 → 本机密码 → 立即锁定** 手动锁定。
- 更改 PIN 在同一面板操作：输入当前 PIN、新的 6 位 PIN 并再次确认。需先验证旧 PIN；成功更改不删除
  配置、收藏、历史或进度。错误尝试累计 5 次后等待约 30 秒，再输入正确 PIN。
- 本机保存随机盐和 PBKDF2 校验记录，不保存明文 PIN，不向数据源发送 PIN；PIN 也不随配置导入导出。
  另一台设备或独立存储入口需要自行设置自己的 PIN。
- 忘记 PIN 无法找回；重新设置需在系统/浏览器清除此网站本机数据，会同时丢失本机配置、收藏和历史。
  已有配置导出可在重新进入后导入。定期备份，不要把清除数据当成无损重置。

## 可选：WebClip 描述文件

推荐使用 Safari 分享菜单；安装页也提供 `/LibreTV.mobileconfig` 作为备用主屏幕图标入口。
这是**未签名、可移除、仅包含一个 WebClip** 的 Apple 描述文件，不是 IPA 或“快捷指令”自动化，
不包含设备管理注册、证书或网络配置，也不会绕过私人网址的访问验证。

1. 在 Safari 安装页下载“LibreTV 快捷图标”。
2. 打开 iPhone **设置 → 已下载描述文件 → 安装**，先检查内容；入口可能随 iOS 版本不同。
   系统可能提示未签名，也可能要求 iPhone 本身的解锁密码；该密码与 LibreTV PIN、ChatGPT 登录不同。
3. 回到主屏幕从该图标打开，按需完成平台验证，保持联网完成缓存，再自行设置此入口的 6 位 PIN。
4. 若不再需要，可在系统 **设置 → 通用 → VPN 与设备管理** 中找到该描述文件并移除。
   移除前导出备份；WebClip、Safari 和原主屏幕入口是否共享本机数据及移除后的影响，仍需实机检查。

安装描述文件不是必需步骤；不愿安装时直接使用 Safari 方法。新包准备发布到原私人 Site，
实际发布状态和验证范围以最终交付记录为准，不把文件已生成当作 iPhone 已成功安装。

## 缓存与更新边界

- 独立版仅注册 `/sw-standalone.js`；原服务器版仍使用 `/sw.js`，两种构建的行为分开。
- 构建完成后运行 `node scripts/prepare-standalone-pwa.mjs <静态导出目录>`。
  脚本将公开 HTML、Next.js JS/CSS/字体及静态 RSC payload、图标和 manifest 列为预缓存，
  将资源摘要、路由映射及 Worker 模板共同计算版本号，再注入独立 Service Worker。
  即使只修复 Worker 代码也使用新缓存，避免安装失败时删除仍在使用的旧缓存。
- 安装时校验每个文件的 SHA-256。允许静态托管把 `/index.html` 规范化到 `/`、`watch.html`
  规范化到 `/watch` 等同站重定向；最终响应地址仍必须属于本站，且内容摘要完全一致。
  HTTP 200 的托管登录页、外域最终响应、缺失资源、网络中断或存储不足都不会作为完整 App
  缓存接受。新版本只有全部资源成功保存后才可激活；失败时保留旧完整版本。
- 缓存键使用静态路径，不把搜索文字、播放签名或 URL 查询中的源配置写进 Cache Storage。
  外部 API、同源 `/api/*`、媒体、Range、POST 等请求均不加入缓存。
- 已准备好的更新只在首页提供手动更新入口，不自动刷新播放页。保留最近两个构建的公开资源，
  减少另一标签页正在播放时丢失旧 JS chunk 的风险；跨多个版本长期不重启的页面仍可能需要重新打开。
- 系统可能因存储压力清理 PWA 缓存/IndexedDB；清除网站数据或卸载也可能删除本机记录。
  本地数据不是云同步，定期在设置中导出备份。

PWA 并未给 iPhone 安装 Node.js。独立版通过迁移为浏览器代码实现免自建后台，
因此不承诺服务器版可使用的所有影视 API 在纯浏览器模式也能使用。
