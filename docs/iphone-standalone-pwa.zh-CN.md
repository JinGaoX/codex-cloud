# iPhone 15 Pro Max 独立版 PWA

此构建把公开应用界面、搜索与详情请求逻辑放在设备端，不运行 Next.js API、搜索聚合服务器或视频代理。
首次安装/更新使用 HTTPS 静态网址分发应用文件；本机缓存完成后，电脑和静态网址暂时不可访问时，
仍能打开已缓存的界面、设置、收藏及观看历史。搜索和视频内容来自你配置的合法数据源，需要联网，
并受 Safari 的 HTTPS、CORS 和媒体兼容性限制。本机缓存界面不等于下载影片。

## 安装及确认本机保存

1. iPhone Safari 打开正式 HTTPS 地址，在托管平台要求时先完成自己的站点访问验证。
2. 分享 → 添加到主屏幕；保留系统提供的“作为网页 App 打开”选项。
3. **从主屏幕图标首次启动时保持联网。** Safari 与主屏幕 App 的缓存和本地数据库可能独立，
   不以 Safari 已经打开过就认定主屏幕 App 已保存。
4. 首页底部会显示“正在将应用保存到本机”；完整界面资源下载成功、Service Worker 激活后，提示消失。
   如提示尚未保存成功，先检查网络和系统存储空间后重新打开，不要把失败安装当作已经可离线。
5. 在主屏幕 App 的设置内添加实际合法 HTTPS API，进行搜索、选集和播放。单个源的 CORS/网络错误
   不影响本地设置、收藏和其他源的结果。拒绝跨域的源无法靠纯 PWA 自行解除限制。
6. 断网后关闭再打开主屏幕图标，确认界面、设置及已有收藏/历史仍可查看；联网后恢复搜索和播放。
   这项仍需真实 iPhone 验证，桌面 Chromium 的离线检查不能替代 iOS 实机。

## 缓存与更新边界

- 独立版仅注册 `/sw-standalone.js`；原服务器版仍使用 `/sw.js`，两种构建的行为分开。
- 构建完成后运行 `node scripts/prepare-standalone-pwa.mjs <静态导出目录>`。
  脚本将公开 HTML、Next.js JS/CSS/字体及静态 RSC payload、图标和 manifest 列为预缓存，
  按内容哈希生成版本号，并在独立 Service Worker 内注入资源摘要与页面路由映射。
- 安装时校验每个文件的 SHA-256；HTTP 200 的托管登录页、重定向、缺失资源、网络中断或存储不足
  都不会作为完整 App 缓存接受。新版本只有全部资源成功保存后才可激活；失败时保留旧完整版本。
- 缓存键使用静态路径，不把搜索文字、播放签名或 URL 查询中的源配置写进 Cache Storage。
  外部 API、同源 `/api/*`、媒体、Range、POST 等请求均不加入缓存。
- 已准备好的更新只在首页提供手动更新入口，不自动刷新播放页。保留最近两个构建的公开资源，
  减少另一标签页正在播放时丢失旧 JS chunk 的风险；跨多个版本长期不重启的页面仍可能需要重新打开。
- 系统可能因存储压力清理 PWA 缓存/IndexedDB；清除网站数据或卸载也可能删除本机记录。
  本地数据不是云同步，定期在设置中导出备份。

PWA 并未给 iPhone 安装 Node.js。独立版通过迁移为浏览器代码实现免自建后台，
因此不承诺服务器版可使用的所有影视 API 在纯浏览器模式也能使用。
