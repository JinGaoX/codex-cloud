# 国内平台精选与随包海报

版本：`2.20.2-personal.12`；分支：`feat/domestic-platform-catalog`。

## 使用方式

首页的电影、剧集分类增加爱奇艺、优酷、腾讯视频。默认先显示爱奇艺电影精选，
原豆瓣周榜、百度热播剧和综艺榜保留。点作品名称仍在用户配置的影视API里搜索，
不把平台官方播放页作为第三方片源，不表示拥有平台会员或官方内容授权。

本轮是按官方公开页面核对的精选片单，随应用版本更新，不是三平台完整片库、
实时热播榜或独播清单。不凭空添加排名、评分、年份、类型或上架状态。
归属证据、核对日期与海报来源保留在 `src/lib/platform-catalog-data.json`，
关于页可展开查看每部作品的官方来源。作品可能在多个平台收录。
腾讯精选也核对其WeTV官方正片信息；不同地区的片库及官方播放权限可能不同，
这里保留真实来源，不将WeTV链接伪装成腾讯大陆站链接。用户仍通过自行配置的合法片源搜索。

## 数据和网络边界

现有60s接口没有三平台分类接口；腾讯分类页不提供可供浏览器跨域读取的响应头，
部分官方页面依赖动态脚本或频繁变化的HTML，不能假设静态PWA可稳定实时读取。
因此不增加新后台或运行时HTML采集，片单直接随共享前端构建。

海报是否需要代理取决于实际图片来源，并不由‘奈飞/国内影片’的分类决定。
精选海报从已核对的官方图片地址取得，压缩成小型WebP文件，随程序按SHA-256完整预缓存。
完成安装/更新与缓存后，六个平台分类及这些海报可离线浏览；程序不需要再向外部图床请求这些图片。
腾讯来源若仅有真实横图，按横图显示，不制造竖版海报。

这不保证首次安装/更新地址在每个地区都能直连，也不改变手机或路由器的代理路由。
小火箭和软路由仍按各自规则决定流量；搜索、影片播放、实时榜单仍需可用网络。
应用没有新增全局‘强制直连’开关，也没有修改用户的代理配置。

## 维护

1. 从平台公开页面核对片名、类别、官方链接和实际海报，不拿待播推荐当已上线片单。
2. 更新数据JSON；海报只允许经过核对的官方HTTPS图片域名，不存密码、Cookie或签名凭据。
3. 在支持环境代理选项的Node版本运行 `npm run catalog:posters`。
   这是显式维护操作，常规构建/手机浏览不会自动下载外部图片。
4. 脚本限制图片大小与解码像素数，输出最大420×700缩略图，保留实际比例；不请求任何视频。
5. 运行类型检查、相关测试与两个静态构建，验证项目路径和根路径的缓存。

影片名称、海报权利归相关权利人。缩略素材用于影片信息展示并保留来源；
程序的AGPL许可证不替代海报的原有权利。
